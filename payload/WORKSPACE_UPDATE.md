3. 两只猫“加入对比”，点“对比并写话术”生成模板。只有主动发送才请求模型。

5. 手机上使用底部四项导航；电脑使用左侧工作区导航。

## 更新包如何使用

更新包可用于现有3.3版或3.4系列整合版，是基于3.3版制作的**轻量增量包**，不包含`dist`、`node_modules`或未改动的大图片，不是从零搭建项目的完整源码。

### 推荐：自动合并到本地项目

1. 解压更新包到一个独立文件夹。
2. 在这个解压后的文件夹打开CMD，执行（路径替换为你实际的项目目录）：

```bat
node apply-update.cjs "D:\1.前期开发的\杂物\新建文件夹 (2)\cat-main"
```

3. 更新器会先备份将被改动的文件到项目内 `workspace-backups`，再复制前端更新文件，并移除三个旧的独立手册入口。
4. 你的 `wrangler.jsonc`、`cloudflare-worker.js`、`cloud-functions`、`migrations`、`.env`、`.dev.vars` 不在更新列表中。D1绑定、远程数据库、激活码、日志和运行时密钥均不更改，不需要重新建库或重新填密钥。
5. 回到实际项目目录执行：

```bat
npm ci
npm test
npm run test:components
npm run build
```

确定更新效果后，再执行 `npx wrangler deploy`，或提交GitHub触发原有自动部署。更新器本身不会部署。

### 手工合并

将更新包的 `payload` 内容按相同路径覆盖到现有项目根目录，并删除以下三个旧文件：

```text
public/manuals/index.html
public/guide/index.html
public/guide-sales/index.html
```

它们由新的顶层 `manuals/index.html`、`guide/index.html`、`guide-sales/index.html` 入口代替。勿覆盖原来的 `wrangler.jsonc` 或密钥配置。通过GitHub网页更新时需包含新增文件和删除操作；不要仅上传`src`。
